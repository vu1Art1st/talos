# Talos 功能规划（Roadmap）

> 本文档为功能设计方案，尚未实现。每项包含使用场景、核心流程与涉及模块，按优先级从高到低排列。

## 1. SLA 修复时限管理

**场景**：安全团队需要对漏洞修复时效进行考核，超期漏洞需及时暴露并催办。

**核心流程**：

1. 系统设置中按等级配置修复期限（默认：严重 7 天 / 高危 15 天 / 中危 30 天 / 低危 90 天）
2. 漏洞进入「已确认」状态时计算 `sla_deadline`（确认时间 + 对应期限）
3. arq 定时任务每日扫描：临期（剩余 ≤ 3 天）与超期漏洞打标，并向漏洞提交人 / 应用负责人发送邮件提醒
4. Dashboard 增加「超期漏洞」卡片与超期趋势；漏洞列表支持按 SLA 状态筛选，超期行红色标记

**涉及模块**：`models/vul.py`（新增 sla_deadline / sla_status 字段）、`services/state_machine.py`（确认时打点）、`workers/`（定时扫描任务）、`api/v1/dashboard.py`、前端 `Dashboard.vue` / `VulnList.vue`、系统设置页。

## 2. 漏洞知识库

**场景**：同类漏洞反复提交，描述与修复建议质量参差不齐，需沉淀标准模板。

**核心流程**：

1. 按漏洞类型维护知识条目：标准描述、危害说明、修复建议、参考链接（富文本）
2. 提交 / 编辑漏洞时选择类型后可「一键套用模板」，自动填充三段富文本
3. Word 导入确认入库时，解析内容为空的字段自动回填知识库模板
4. 支持从已有高质量漏洞记录「存为模板」

**涉及模块**：新增 `models/knowledge.py` + `api/v1/knowledge.py`、前端知识库管理页、`VulnForm.vue` 套用入口、`services/importer.py` 回填逻辑。

## 3. 扫描器报告接入

**场景**：企业已有 AWVS / Nessus / Xray 等扫描器，希望扫描结果自动汇入平台统一闭环。

**核心流程**：

1. 导入中心新增「扫描报告导入」：上传扫描器导出文件（AWVS XML、Nessus .nessus、Xray JSON）
2. 后台按扫描器类型解析为统一漏洞草稿（等级映射、去重指纹 = 类型 + URL + 参数）
3. 复用现有「批次 → 预览 → 修正 → 确认入库」流程；与已有漏洞指纹重复的记录标记「疑似重复」
4. 入库来源标记为对应扫描器，便于统计各来源漏洞占比

**涉及模块**：`services/` 新增 scanner_parsers（每种扫描器一个解析器）、`constants.py`（VUL_SOURCE 扩展）、复用 `models/import_batch.py` 与 `ImportPreview.vue`。

## 4. 通知渠道扩展

**场景**：邮件时效性差，团队日常在钉钉 / 企业微信 / 飞书协作，需要即时触达。

**核心流程**：

1. 系统设置中配置通知渠道：通用 Webhook、钉钉 / 企业微信 / 飞书机器人（URL + 签名密钥）
2. 事件订阅矩阵：漏洞提交、状态流转、SLA 临期 / 超期等事件可分别勾选渠道
3. 事件发生时由 arq 异步推送消息卡片（含漏洞标题、等级、链接），失败重试 3 次并记录日志

**涉及模块**：新增 `services/notify.py`（渠道适配器模式）、`models/notify_channel.py`、`workers/` 推送任务、`services/state_machine.py` 事件挂钩、系统设置页。

## 5. CVSS 3.1 评分计算器

**场景**：等级评定依赖个人经验，需要业界标准量化依据。

**核心流程**：

1. 提交 / 编辑页内嵌 CVSS 3.1 向量选择器（AV / AC / PR / UI / S / C / I / A 八个维度按钮组）
2. 前端实时计算基础分并展示向量字符串（如 `CVSS:3.1/AV:N/AC:L/...`）
3. 分数自动换算等级建议（9.0+ 严重 / 7.0+ 高危 / 4.0+ 中危 / 其余低危）并回填 risk_score，允许人工覆盖
4. 详情页展示向量与分数明细

**涉及模块**：前端新增 `components/CvssCalculator.vue`、`VulnForm.vue` / `VulnDetail.vue` 集成、`models/vul.py`（cvss_vector 字段）。

## 6. 定期报表订阅

**场景**：管理层需要周报 / 月报了解安全态势，目前依赖人工整理。

**核心流程**：

1. 报告中心新增「订阅」：选择周期（每周一 / 每月 1 日）、统计范围（全部或指定应用）、收件人列表
2. arq 定时任务到期自动生成报表：新增 / 修复 / 超期漏洞统计、等级分布、Top 应用，复用现有报告构建与导出链路产出 Word/PDF
3. 邮件附件分发，报告中心留档可下载

**涉及模块**：`models/report.py`（订阅表）、`workers/`（cron 任务）、复用 `services/report_builder.py` 与导出服务、前端报告中心订阅管理页。

## 7. 开放 API 与个人访问令牌

**场景**：CI/CD 流水线中的安全扫描环节需要自动提交漏洞、查询修复状态（DevSecOps 集成）。

**核心流程**：

1. 用户中心生成个人访问令牌（PAT）：命名、选择权限范围（只读 / 可提交）、设置有效期，仅创建时明文展示一次
2. API 认证层支持 `Authorization: Bearer <PAT>`（与 JWT 并存），按令牌范围鉴权
3. 提供 OpenAPI 使用文档与流水线示例（提交漏洞、查询状态、拉取统计）
4. 令牌可随时吊销，调用记录入审计日志

**涉及模块**：`models/token.py`、`core/security.py`（认证分支）、`api/v1/tokens.py`、用户中心前端页。

## 8. 登录与操作审计

**场景**：等保合规与内部安全要求：谁在什么时间登录、做了什么敏感操作必须可查。

**核心流程**：

1. 记录登录日志（成功 / 失败、IP、User-Agent）与敏感操作日志（用户 / 角色变更、漏洞删除、导出、令牌操作、配置修改）
2. 新增「审计日志」页面：按用户 / 类型 / 时间范围筛选，支持导出 CSV
3. 连续登录失败锁定策略（如 5 次失败锁定 15 分钟）
4. 日志仅系统管理员可见，保留期限可配置

**涉及模块**：`models/audit.py`、登录接口与各敏感 API 挂钩（依赖注入统一记录）、`api/v1/audit.py`、前端审计页、`PERMISSIONS` 新增 `audit:view`。

---

**优先级建议**：第一批（1、2、8）夯实闭环管理与合规基础；第二批（3、4）打通外部输入与即时触达；第三批（5、6、7）提升专业度与生态集成。
