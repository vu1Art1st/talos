# Talos UI 设计规范

> 本文是 Talos 前端视觉与交互的唯一详细执行规范。`AGENTS.md` 是项目规范入口，新页面、改版和
> UI Review 均须同时遵守本文与 `AGENTS.md`。旧页面与本文冲突时，以本文为准；存量问题在相关功能
> 改动中顺手收敛，不为纯样式迁移扩大业务改动范围。

## 1. 设计目标

Talos 面向漏洞管理员、渗透测试人员、资产负责人和系统管理员。界面需要支持高频扫描、比较、判断
和处置，因此优先保证信息秩序与操作效率。

- 信息优先：任务、状态、风险和下一步操作优先于装饰。
- 一致可预期：相同语义使用相同组件、颜色、文案和交互位置。
- 明暗同源：浅色和暗色使用同一套语义令牌，但各自采用 Radix 对应色阶。
- 克制表达：不用营销式排版、装饰性动画、无意义卡片和过度强调。
- 面向岗位：文案使用 Talos 业务术语，准确、简练、可执行。
- 光学舒适：浅色模式避免大面积最高对比文字，以层级而不是刺眼反差组织信息。

## 2. 文案与信息架构

### 2.1 文案规则

- 禁止使用中点字符 U+00B7 作为界面文案分隔符。多个信息项拆成独立列、标签、行或空白分组，
  不引入另一个装饰符号替代中点。
- 删除复述标题的副标题、解释控件如何使用的常驻说明、营销宣传语和无法帮助决策的背景文字。
- 按页面面向人群遣词。漏洞、工单、复测、报告、资产等术语以产品字典为准，不另造同义词，
  不使用过度口语化、拟人化或营销化表达。
- 操作文案以动词开头并直接说明结果，例如「新增漏洞」「发起复测」「导出报告」。
- 状态文案使用稳定的名词或状态短语，例如「已修复」「复测中」「待确认」。
- 按钮名称必须与操作结果一致。不要使用脱离上下文的「确定」「处理」「继续」。
- 错误信息说明发生了什么、已知原因和处理路径。原因未知时不要编造，给出可靠的重试、返回或
  联系管理员路径。
- 空状态只说明当前为空和下一步操作，不加入功能科普、快捷键教学或装饰性鼓励语。
- 同一区域只保留一个主操作。次要操作降低视觉权重，低频操作可收进菜单，但必须保持可发现。

### 2.2 信息优先级

页面按「标题与上下文 → 筛选或主操作 → 核心内容 → 辅助元数据」组织。

- 列表优先支持扫描、排序和比较；详情优先呈现当前状态和下一步动作。
- 表单元数据放在用户需要做决定的位置，不在表单外重复解释。
- 卡片只用于重复条目、弹窗和确有边界的工具容器，不用于装饰页面分区。
- 同一区域只突出一个视觉重点。层级优先通过位置、间距、字重和文字色表达。
- 简单选择放在筛选栏、字段、行内操作或确认步骤中，不为单一选择增加额外弹窗。
- 危险、不可逆、跨范围和覆盖他人数据的操作必须确认；普通查看、切换和可恢复编辑不得反复打断。
- 加载、保存、失败和重试反馈靠近受影响内容，不把局部失败升级为整页错误。

## 3. Radix UI Colors 色彩系统

### 3.1 唯一色彩来源

Talos 的全部界面颜色统一来自 [Radix UI Colors](https://www.radix-ui.com/colors) 的 12 级色阶和
Alpha 色阶，包括页面、浮层、文字、边框、Element Plus、Tailwind、图表、标签、头像和登录页装饰。

- 禁止在组件内新增十六进制、RGB、HSL、`color-mix()` 或 Tailwind 默认色。
- `frontend/src/style.css` 的 `--tl-*` 是业务语义令牌；`--el-*`、Tailwind `@theme` 和图表
  色板只能引用语义令牌或批准的 Radix 色阶。
- 浅色和暗色分别使用 Radix 同名步骤，不通过混白、混黑或透明度手工推导另一主题。
- 透明度、悬停和选中背景优先使用 Radix Alpha 色阶。
- 后端 `backend/app/constants.py` 是字典文案与色族语义的唯一来源；前端只接收色族名并通过
  `frontend/src/utils/colors.ts` 解析明暗色阶。
- Tailwind 的 `text-gray-*`、`bg-gray-*`、`border-gray-*` 类名作为兼容层保留，值统一映射到
  `--tl-gray-*`，其底层来源是 `sage`。不得据此恢复独立灰阶或新增默认 Tailwind 色。

### 3.2 色族映射

| 用途 | Radix 色族 | 说明 |
|---|---|---|
| 中性表面、边框和文字 | `sage` | 延续原系统的微暖灰绿中性底色 |
| 品牌、主要操作和安全状态 | `jade` | 延续原系统的薄荷绿品牌识别 |
| 低危、链接和普通信息 | `sky` | 延续原系统的淡蓝信息色 |
| 辅助信息与蓝系分类 | `blue` | 仅用于需要与 `sky` 区分的业务语义 |
| 严重风险、错误和阻断 | `red` | 严重漏洞、失败和危险操作 |
| 高危风险 | `orange` | 高危漏洞和高优先级提醒 |
| 中危风险、警告和待处理 | `amber` | 中危漏洞、等待和告警 |
| 复测未通过等独立失败语义 | `ruby` | 与普通危险操作区分 |
| 合并状态等流程分类 | `violet` | 流程或合并语义 |
| 漏洞类型扩展 | `pink` / `cyan` / `teal` / `grass` | 通过色相区分业务分类 |

字典色族必须保持稳定。不得因为主题变化换色族，也不得在视图中把同一业务状态映射成不同颜色。

| 业务语义 | 浅色与暗色色族 | 使用约定 |
|---|---|---|
| 严重 | `red` | 严重漏洞、未修复、危险操作 |
| 高危 | `orange` | 高危漏洞和高优先级任务 |
| 中危 | `amber` | 中危漏洞、等待和临期 |
| 低危 | `sky` | 低危漏洞、复测中和信息入口 |
| 安全 | `jade` | 安全状态、已修复、已完成 |
| 复测未通过 | `ruby` | 仅用于派生展示状态 |
| 合并 | `violet` | 导入合并等流程状态 |
| 普通、忽略、未开始 | `sage` | 中性状态和兜底 |

风险等级、状态和分类必须同时显示文字，不能只依靠颜色传义。

- 漏洞等级固定按「严重 → 高危 → 中危 → 低危 → 安全」排序，不得跟随接口聚合顺序。
- 漏洞状态固定按「未修复 → 修复中 → 复测中 → 已修复 → 已忽略 → 暂不处理」组织。

### 3.3 12 级色阶规则

| 色阶 | 标准用途 |
|---|---|
| `1` | 页面中的最高层表面或应用表面 |
| `2` | 页面背景、表格隔行底色 |
| `3` | 次级表面、表头、柔和标签背景 |
| `4` | 悬停、激活和选中表面 |
| `5` | 更强的选中或交互背景 |
| `6` | 分隔线和弱边框 |
| `7` | 控件边框和焦点轮廓基色 |
| `8` | 悬停边框和强焦点环 |
| `9` | 实心品牌或状态背景 |
| `10` | 实心背景悬停、弱化前景 |
| `11` | 正文、次级文字和可操作文字 |
| `12` | 标题、关键数字、最高强调前景 |

强制约束：

- 大面积正文使用 `11`，标题和关键数字使用 `12`。不得让所有文本都使用 `12`。
- 可操作文字和 14px 正文达到至少 4.5:1；12px 辅助信息达到至少 3:1。
- 浅色模式下，正文优先使用 `sage-11`，辅助信息优先使用 `sage-10`；`sage-12` 只用于短标题、
  短标签中的主信息和关键数字。
- 暗色模式下，正文使用对应色族的 `11` 或 `12`，辅助信息不得使用暗色 `9`。
- 普通分隔线使用 `6`，控件边框使用 `7`，焦点和悬停边框使用 `8`。
- 柔和状态标签使用 `3` 背景、`6` 边框、`11` 文字；不得手工计算透明度。
- 实心按钮使用 `9` 背景、`10` 悬停背景，前景必须经过实际对比度验证，不默认所有色族配白字。
- 图表数据填充、图例色点、表格状态点和趋势条使用 `9` 级实心数据色；文字、柔和标签使用 `11` 级，二者不得混用。
- 键盘焦点必须清晰可见，颜色不能成为唯一状态提示。

### 3.4 浅色模式的舒适对比度

浅色模式不使用单一“越高越好”的文字规范，而采用稳定的三级前景：

| 前景 | Radix 浅色步骤 | 典型用途 |
|---|---|---|
| 强调文字 | `sage-12` | 16px 标题、关键指标、页面标题、弹窗标题 |
| 正文文字 | `sage-11` | 正文、表格、表单、按钮、导航和 14px 可操作内容 |
| 辅助文字 | `sage-10` | 时间戳、占位符、弱标签和 12px 辅助信息 |

在 `sage-1` 表面上，这三级的对比度约为 `16:1`、`5.8:1`、`3.8:1`。这个分层能降低大面积正文的
视觉硬度，同时保留可操作文字和关键信息的清晰度。暗色模式将主文字提升到 `sage-12`、辅助文字
提升到 `sage-11`，避免暗色低对比。

### 3.5 语义令牌

保留既有 `--tl-*` 名称以降低迁移成本，当前语义映射如下：

| 语义令牌 | 浅色映射 | 暗色映射 | 用途 |
|---|---|---|---|
| `--tl-bg` | `sage-2` | `sage-1` | 应用背景 |
| `--tl-surface` | `sage-1` | `sage-2` | 普通表面 |
| `--tl-surface-2` | `sage-3` | `sage-3` | 次级表面 |
| `--tl-surface-3` | `sage-4` | `sage-4` | 激活表面 |
| `--tl-border` | `sage-6` | `sage-6` | 0.5px 分隔线与弱边框 |
| `--tl-border-strong` | `sage-7` | `sage-7` | 控件与悬停边框 |
| `--tl-text-strong` | `sage-12` | `sage-12` | 标题和关键数字 |
| `--tl-text-1` | `sage-11` | `sage-12` | 默认正文 |
| `--tl-text-2` | `sage-11` | `sage-11` | 次级正文 |
| `--tl-text-3` | `sage-10` | `sage-11` | 辅助文字 |
| `--tl-primary` | `jade-9` | `jade-9` | 品牌实心背景 |
| `--tl-primary-hover` | `jade-10` | `jade-10` | 品牌背景悬停 |
| `--tl-primary-text` | `jade-11` | `jade-11` | 品牌文字、链接和图标 |
| `--tl-primary-soft` | `jade-3` | `jade-3` | 品牌柔和背景 |
| `--tl-on-primary` | `sage-12` | `sage-1` | 品牌实心底上的前景 |
| `--tl-focus` | `jade-8` | `jade-8` | 焦点环 |
| `--tl-success` | `jade-11` | `jade-11` | 成功文字 |
| `--tl-success-bg` | `jade-9` | `jade-9` | 成功实心背景 |
| `--tl-warning` | `amber-11` | `amber-11` | 警告文字 |
| `--tl-warning-bg` | `amber-9` | `amber-9` | 警告实心背景 |
| `--tl-danger` | `red-11` | `red-11` | 危险文字 |
| `--tl-danger-bg` | `red-9` | `red-9` | 危险实心背景 |
| `--tl-info` | `blue-11` | `blue-11` | 普通信息文字 |
| `--tl-blue` | `sky-11` | `sky-11` | 蓝系业务分类 |

同一语义色不得同时承担实心背景和文字前景。迁移旧令牌时按背景、文字、柔和背景和 Alpha 状态
拆分角色。

### 3.6 表格色彩

列表表格默认启用隔行变色，使用独立的表面层级：

| 状态 | 浅色映射 | 暗色映射 | 令牌 |
|---|---|---|---|
| 基础行 | `sage-1` | `sage-2` | `--tl-surface` |
| 隔行 | `sage-2` | `sage-3` | `--tl-table-stripe` |
| 表头 | `sage-3` | `sage-3` | `--tl-table-head` |
| 行悬停 | `sage-4` | `sage-4` | `--tl-table-hover` |

- 隔行底色必须比基础行深一级，但不能成为强调背景。
- 悬停态必须与隔行底色区分，且对普通行和隔行使用同一悬停色。
- 表格边界使用 `0.5px`，不得通过粗线或阴影分隔行列。
- 表格行内等级和状态使用「色点 + 文字」；筛选器、详情和表单使用柔和标签。

## 4. 排版

### 4.1 字号与字重

界面文字只允许三级字号，最小值为 12px：

| 层级 | 字号 | 字重 | 使用范围 |
|---|---|---|---|
| 辅助 | 12px | 400 或 500 | 时间戳、表头辅助、状态补充、说明和图表刻度 |
| 正文 | 14px | 400、500 或 600 | 正文、表格、表单、按钮、导航和绝大多数控件 |
| 标题 | 16px | 600 | 页面标题、弹窗标题、区块标题和关键指标 |

- 不增加第四档字号，也不使用低于 12px 的字号。
- 层级不足时优先调整字重、`--tl-text-*`、间距和分组，不放大正文。
- 页面和组件内的标题不得超过 16px。
- 关键数字使用 600 字重和 tabular-nums，不使用巨大字号制造视觉冲击。
- 字距保持 0，不使用负字距。英文标签不使用全大写。
- 文案必须覆盖中英文混排、长英文单词和加粗场景下的换行与截断。

## 5. 间距、对齐与形状

### 5.1 间距与光学对齐

- 间距以 4px 为基准，优先使用 4、8、12、16、24、32px。
- 1px 和 2px 只用于光学校正或细线定位。
- 同一行的图标、文字和控件按视觉重心对齐，不机械依赖包围盒中心。
- 图标与单行文字视觉中心对齐，多行文本与首行基线对齐。
- 表头、单元格、工具栏按钮和筛选项共享稳定垂直中心线。
- 相邻操作组间距小于组间间距。容器负责内边距，子元素负责同级间隔。
- 控件尺寸稳定。加载、错误、计数和悬停状态不得改变布局尺寸。
- 页面文字不得遮挡前后内容。长内容需要换行、截断或响应式布局，而不是压缩字号。

### 5.2 圆角与同心关系

圆角只使用以下三档：

| 圆角 | 用途 |
|---|---|
| `0` | 页面分区、工具栏、表格和无边界表面 |
| `4px` | 输入框、按钮、标签和紧凑控件 |
| `8px` | 卡片、弹窗、菜单和其他明确浮层 |

- 页面分区、工具栏和全宽列表默认不使用圆角。
- 胶囊形只保留给头像、开关、进度条等本身具有胶囊语义的控件。
- 嵌套表面同心：`外层圆角 = 内层圆角 + 内外层间距`。
- 内层没有背景、边框或可点击边界时，不额外设置圆角。

### 5.3 边框与阴影

- 所有边框、分隔线、输入框描边和轮廓线使用 `0.5px`。
- 边框颜色来自 Radix `6` 至 `8` 级，不使用半透明黑或白临时替代。
- 优先使用边框、背景和间距建立层级，不用阴影模拟边框。
- 卡片、表格、工具栏和页面分区不使用阴影。
- 只有弹窗、下拉菜单、命令面板和登录卡等确实浮于页面之上的元素可使用阴影。
- 阴影只提示层级，颜色来自 Radix 中性 Alpha 色阶。
- 禁止在卡片左侧、顶部或底部添加彩色强调线。

## 6. 动效

- 默认不使用动画。列表刷新、卡片悬停和标签切换不得添加装饰性过渡。
- 仅当状态反馈、加载、浮层出现或内容替换需要帮助理解时使用动效。
- 必要动效使用 `ease-out`，基础时长 250ms，不得使用超出该范围的随机时长。
- 禁止弹跳、回弹、缩放呼吸、视差、持续漂浮和循环装饰动画。
- 图表入场动画仅在确有数据变化提示时使用，时长不超过 250ms，且不循环。
- 必须尊重 `prefers-reduced-motion`，关闭动画后功能与状态反馈仍完整。

## 7. 组件与页面规则

### 7.1 表单

- 标签位于字段上方或稳定的左对齐列中，同一表单不得混用两套布局。
- 校验统一使用 Element Plus `rules`，错误内联显示在字段下方。
- 表单控件使用 4px 圆角、0.5px 边框，聚焦时使用清晰的 `jade-8` 焦点环。
- 表单弹窗禁止点击遮罩关闭，提交按钮必须绑定 `:loading`。
- 字段说明只在影响填写判断时保留，常驻解释应删除。

### 7.2 列表与表格

- 列表页的搜索、筛选与主操作统一放在正文上方的 `FilterToolbar`，不得在卡片标题区再放一套工具栏。
- 操作列固定在右侧，按钮必须单行排列；宽度不足时优先精简次要操作，不得通过换行拉高行高。

- 列表首屏必须显示 `v-loading`，禁止空白闪现。
- 表格默认 `stripe`，使用本文 3.6 的隔行和悬停规则。
- 行内操作用文字按钮或图标按钮，图标必须有可理解名称和 tooltip。
- 分页、排序和筛选应可预期，操作后保持当前上下文和滚动位置。
- 移动端卡片列表复用同一数据与状态排序，不另造业务口径。

### 7.3 弹窗、抽屉与确认

- 宽度三档：S=480、M=640、L=800；命令面板 560px 单列。
- 单场景只允许一层弹窗，表单弹窗必须 `:close-on-click-modal="false"`。
- 行内删除使用 `el-popconfirm`；批量或危险操作使用 `ElMessageBox.confirm`，
  确认按钮使用危险语义。
- 版本冲突、覆盖他人内容和不可恢复操作必须由用户明确选择，禁止静默覆盖。

### 7.4 登录页品牌例外

登录页是 Talos 唯一的品牌视觉例外，用于建立产品识别，不属于运营页面的装饰范式。

- 允许使用受控点阵背景、三组 Radix Alpha 径向色晕、装饰角、登录卡浮层阴影和品牌渐变按钮。
- 所有颜色仍来自 Radix 色阶和 `--tl-*` 令牌，禁止新增任意色值。
- 图形保持静态，不使用漂浮、呼吸、旋转或自动播放动画。
- 品牌名称与标题保持 16px/600，正文与控件 14px，辅助信息 12px。
- 登录卡宽度保持在 420px 以内，窄屏使用 16px 安全边距。
- 背景层不得影响表单可读性、焦点可见性或移动端滚动。
- 登录页之外不得复用该装饰组合；其他页面不得添加装饰性径向光斑或多色渐变。

## 8. 可访问性与明暗模式

- 14px 正文和可操作文字至少达到 4.5:1；12px 辅助文字至少达到 3:1。
- 禁用态必须明显区别于可操作态，但不能低到无法辨认。
- 风险等级使用色点和文字，错误同时提供文本说明。
- 浅色与暗色分别使用 Radix 对应色阶，不得只做亮度反转。
- 新页面和改版页面必须在浅色、暗色、窄屏和 200% 缩放下检查。
- 重点检查对齐、换行、截断、点击区域、焦点环和文字遮挡。

## 9. 技术落地

新增色族或字典色时必须同步以下入口：

1. `frontend/src/main.ts` 引入 Radix 浅色、暗色及 Alpha CSS。
2. `frontend/src/style.css` 建立或复用语义令牌。
3. `frontend/src/utils/colors.ts` 扩充 `ColorFamily`、识别集合和解析逻辑。
4. `frontend/src/utils/chartTheme.ts` 增加图表色映射。
5. 后端 `backend/app/constants.py` 使用批准的色族名。
6. 更新 `frontend/src/utils/__tests__/designTokens.spec.ts` 和相关颜色契约测试。

禁止在视图中直接写 `var(--jade-9)` 作为业务字典色。业务字典色必须通过 `/meta` 和
`colors.ts` 出口；只有纯 UI 场景可以引用语义令牌。

## 10. UI Review 检查清单

- 文案不存在 U+00B7 分隔符，也没有复述标题、解释常识或营销化描述。
- 页面只有一个主操作，按钮文案直接说明操作结果，业务术语与字典一致。
- 所有颜色可追溯到 Radix 色阶和语义令牌，组件内没有新增散落色值。
- 浅色正文不是全域 `sage-12`，标题与正文层级清晰且视觉舒适。
- 暗色辅助文字没有落在低对比的 `9` 级。
- 表单和表格在浅色、暗色下均保留隔行纹理，悬停态可辨识。
- 字号只使用 12px、14px、16px，正文默认 14px。
- 所有边框和分隔线均为 `0.5px`。
- 圆角只使用 0、4px、8px，嵌套表面满足同心关系。
- 卡片和工具栏没有阴影，登录页之外的装饰渐变与光斑已移除。
- 动效仅用于必要状态反馈，使用 `ease-out` 和 250ms，并支持减少动态效果。
- 简单选择位于用户本来就会做选择的区域，没有无意义确认或弹窗层级。
- 登录页在桌面和窄屏均保持品牌识别、表单可读性和安全边距。
- 浅色和暗色模式均完成视觉检查，文字、图标、边框和状态色没有对比度或对齐问题。
