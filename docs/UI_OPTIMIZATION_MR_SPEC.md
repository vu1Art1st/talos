# Talos UI 优化实施基线与三批 MR 方案

> 目标：基于已通过评审的三个 demo（登录页、安全态势页、渗透测试工单页），给出可直接执行的统一实施规格，并拆分为三批可独立合入的 MR。
>
> 适用范围：`frontend/src/views`、`frontend/src/components`、`frontend/src/style.css` 及与页面样式相关的复用层。

## 1. 统一实施基线（所有 MR 必须遵守）

### 1.1 设计目标

1. 在保持现有规范化成果的前提下，恢复更柔和的观感与适度视觉增强。
2. 业务页面保持高信息密度与高可读性，不引入营销化或装饰性干扰。
3. 二次元气质仅用于“人”相关信息表达，不侵入核心数据区。

### 1.2 全局约束

1. 色彩体系仅使用 Radix UI Colors 映射后的语义令牌，不允许新增裸色值。
2. 字号仅允许三档：`12px / 14px / 16px`，最小可用字号 `12px`。
3. 边框与分隔线统一 `0.5px`。
4. 圆角仅允许 `0 / 4px / 8px`。
5. 动效默认关闭，必要动效统一 `ease-out 250ms`。
6. 文案禁用中点字符 `·` 作为分隔符，禁止冗余解释性描述。
7. 业务页面不使用装饰性大阴影与装饰性渐变；登录页可作为品牌视觉例外。

### 1.3 布局与间距基线

1. 应用壳层：侧栏 `216px`，主区自适应；主内容区最大宽 `1560px`。
2. 顶栏：高度 `52px`，左右内边距 `24px`。
3. 工具栏：控件高度以 `32px` 为主，容器内边距 `10px 12px`，控件间距 `8px`。
4. 统计卡与业务面板：卡片圆角 `8px`，内部控件圆角 `4px`，满足同心圆规则。
5. 4px 网格间距体系：仅用 `4/8/12/16/24/32`。

### 1.4 字体与排版基线

1. 标题与关键指标：`16px / 600`。
2. 正文、控件、表格主信息：`14px / 400~600`。
3. 辅助信息（时间、说明、占位、次级标签）：`12px / 400~500`。
4. 数字、ID、时间列统一使用 tabular-nums。

### 1.5 配色与主题基线

1. 中性色：`sage`；品牌与安全：`jade`；信息：`sky`。
2. 风险语义：`red / orange / amber`；扩展：`ruby / violet / pink / cyan / teal / grass / blue`。
3. 浅色模式文本层级：
   - 强文本：`sage-12`
   - 主文本：`sage-11`
   - 辅文本：`sage-10`
4. 表格分层：
   - 表头：`--tl-table-head`
   - 隔行：`--tl-table-stripe`
   - 悬停：`--tl-table-hover`
5. 状态展示必须“颜色 + 文案/图形”双通道表达，禁止纯颜色传义。

### 1.6 状态与反馈基线

1. Hover 仅改变颜色层，不改变尺寸。
2. Active/Selected 使用语义色 `a3` 背景与强调前景。
3. Disabled 可见可判读，且不可触发交互。
4. Loading：按钮必须 `:loading`；首屏列表/详情必须有加载态，禁止空白闪烁。
5. Empty：统一空状态组件并提供下一步动作。
6. Error：字段错误贴字段下方，页面错误提供可执行重试路径。

### 1.7 响应式基线

1. 断点：`1180px`、`760px`、`420px`。
2. `<=1180px`：侧栏折叠为图标导航。
3. `<=760px`：侧栏隐藏，工具栏重排，操作区纵向堆叠。
4. `<=420px`：登录卡片收紧内边距，保证不裁切、不溢出。

### 1.8 可访问性基线

1. 14px 正文与控件文本对比度 >= 4.5:1，12px 辅助文本 >= 3:1。
2. 焦点态统一 `0.5px` 轮廓 + `2px` offset。
3. 键盘可完成核心路径（Tab、Enter、Esc、快捷键）。
4. 弹层与关键交互具备语义标注（`role`、`aria-*`、label 绑定）。
5. 支持 `prefers-reduced-motion`。

### 1.9 暗色模式基线

1. 暗色仅调整颜色，不改布局结构。
2. 暗色辅助文字使用 `sage-11`，避免过灰与低对比。
3. 表格隔行、悬停、状态色在暗色下必须可区分。

## 2. 三批 MR 拆分

## MR-1 登录页视觉与交互优化

### 2.1 目标

1. 恢复登录页品牌识别度与柔和视觉层次。
2. 保持登录流程简洁与高可用，避免信息噪音。

### 2.2 适用范围

1. 登录页视图及其局部样式。
2. 登录表单控件状态与错误提示表现。

### 2.3 实施项

1. 背景：引入受控径向渐变与轻点阵纹理（仅登录页）。
2. 卡片：保留 `8px` 圆角与受控阴影，边框维持 `0.5px`。
3. 主按钮：允许品牌渐变与轻阴影，hover 使用亮度微调。
4. 表单：
   - 输入容器高度 `44px`。
   - 聚焦状态使用语义焦点色。
   - 密码显隐、错误提示、禁用加载态完整可用。
5. 角色表达：值守角色只出现在卡片辅助区，不影响主流程。
6. 文案：删解释型冗余内容，使用业务导向短语。

### 2.4 验收标准

1. 1440px、390px 下登录页无裁切、无横向滚动。
2. 错误态、加载态、密码显隐可完整键盘操作。
3. 色值全部来自语义令牌，无裸色。
4. 文案不出现中点分隔符。

## MR-2 安全态势页视觉层次与图表表现优化

### 2.5 目标

1. 在不增加噪音的前提下增强数据可读性与层次。
2. 保持筛选、趋势、分布、排行的扫描效率。

### 2.6 适用范围

1. 态势页工具栏、统计区、图表区、部门看板表格。
2. 趋势图 tooltip 与分段切换交互。

### 2.7 实施项

1. 工具栏控件按统一高度与间距对齐，主次操作清晰分层。
2. 统计卡保持无阴影，通过边框与背景层区分。
3. 趋势图：
   - 允许数据语义渐变填充（仅图表数据层）。
   - 点位 hover 与 tooltip 提示增强。
4. 环图与条图：颜色语义与风险等级保持一致。
5. 表格：恢复隔行纹理，hover 不覆盖结构可读性。
6. 弹层（保存视图）：允许受控阴影，遵守焦点管理与 Esc 关闭。

### 2.8 验收标准

1. 同屏可完成筛选、切换趋势、打开保存视图。
2. 图表与表格在明暗模式均可读，语义一致。
3. 表格隔行与悬停关系稳定，不闪烁不冲突。
4. 文案长度适配容器，无截断歧义。

## MR-3 渗透测试工单页流程感与操作效率优化

### 2.9 目标

1. 强化工单流程状态表达，降低筛选与处理成本。
2. 保持表格密度与操作直达性。

### 2.10 适用范围

1. 工单页筛选栏、统计卡、流程条、工单列表、抽屉、创建弹窗。

### 2.11 实施项

1. 筛选区：关键词、状态、部门、预设筛选组织为单层决策流。
2. 统计卡：维持低噪音信息块，支持筛选联动。
3. 流程条：阶段信息与当前节点高亮清晰，连接线细化至 `0.5px`。
4. 列表：
   - 默认隔行纹理。
   - 状态使用 dot-tag（颜色 + 文案）。
   - 风险等级使用 soft-tag。
5. 抽屉：允许受控阴影，保持详情信息分组清晰。
6. 新建弹窗：字段结构简洁，错误与提交反馈明确。

### 2.12 验收标准

1. 常见路径（筛选、查看详情、新建工单、导出）一步到位。
2. 列表在 390px 与桌面视图均保持可操作性。
3. 抽屉/弹窗焦点陷阱、Esc、遮罩关闭行为一致。
4. 所有状态不依赖颜色单通道表达。

## 3. 合入顺序与交付要求

### 3.1 合入顺序

1. 先合入 MR-1（登录页）
2. 再合入 MR-2（安全态势页）
3. 最后合入 MR-3（渗透测试工单页）

### 3.2 每批 MR 必带交付物

1. 改动清单：页面、组件、样式令牌映射点。
2. 对照截图：至少含桌面与窄屏、浅色与暗色。
3. 可访问性检查记录：焦点态、键盘路径、对比度抽检。
4. 回归清单：加载/空状态/错误提示/禁用态。

### 3.3 全量验收标准（三批完成后）

1. 三个页面视觉风格统一，且保留各自业务语义差异。
2. 颜色、字号、圆角、边框、动效完全符合全局基线。
3. 明暗模式与三断点适配稳定，无横向溢出、无遮挡。
4. 文案清晰专业，无中点分隔符、无解释型冗余文本。
5. 交互状态完整：悬停、点击、禁用、加载、空状态、错误提示全覆盖。

## 5. 二次升级实施记录（最终口径）

### 5.1 设计依据与边界

1. `docs/DESIGN_SYSTEM.md` 是唯一强制规范，三个 demo 只作为视觉方向和细节参考，不作为页面结构、文案或数据模型的实现模板。
2. 二次升级只提升共享壳层、登录页、安全态势页和渗透测试工单页的视觉与交互质量，不改变接口、路由、业务状态机和数据结构。
3. 二次元视觉只保留在登录页这一品牌例外中；业务页面通过角色头像、用户身份和数据密度表达产品个性，不增加装饰性角色模块。

### 5.2 编码修复

1. 清除此前写入的 U+FFFD 替换字符，恢复登录页值守文案、页脚文案与页面口令。
2. 调整写入流程，后续中文文案必须保持 UTF-8，禁止出现替换字符。
3. 对 `frontend/src` 和本文件执行 U+FFFD 替换字符扫描，结果为空。

### 5.3 共享壳层

1. 桌面侧栏调整为 `216px`，顶栏 `52px`，品牌区最小高度 `68px`，主内容边距为 `18/24/40`。

3. 移动导航使用 `aria-expanded`、`aria-controls`、`aria-modal`、`aria-hidden` 和 `inert`，避免关闭状态下的键盘穿透。
4. 侧栏滚动条隐藏，避免业务页面出现与内容无关的独立滚动条。
5. 移除业务页中的值守角色卡片，避免把登录页品牌例外扩散到核心工作区。

## 6. 全系统数据色二次统一

### 6.1 调整原则

1. 漏洞等级、状态、类型的色族仍以 `backend/app/constants.py` 为唯一来源。
2. 图表填充、趋势条和图例色点使用 Radix `9` 级实心色；文字与柔和标签继续使用 `11` 级。
3. 色点只承担辅助识别，等级和状态始终保留文字，不扩大颜色独占语义的范围。

### 6.2 全系统落地

1. `frontend/src/utils/colors.ts` 新增 `solidColor()`，`dotStyle()` 统一改用实心 `9` 级数据色。
